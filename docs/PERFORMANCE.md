# 接口与 SQL 性能检查

2026-10-30 检查了 `app.py` 的全部 17 条路由，以及采集、备份和迁移脚本的 SQL。查询值均使用参数绑定；唯一动态更新字段来自固定白名单。

## 接口检查结果与修复

| 接口 | 检查及处理 |
| --- | --- |
| 登录、改密 | PBKDF2 同时最多执行 2 次，忙时返回 429；保留原有登录失败限制、密码规则和会话撤销行为 |
| 当前会话、退出 | 会话哈希按主键查询；CSRF 检查保留；写入锁等待从 15 秒缩短为 1 秒，繁忙返回 503 |
| 用户列表 | 域名数量与连接总数改为单次分组查询，消除每个用户两次额外 SQL |
| 创建、启禁用、重置 | 仍使用原有 Xray API 和失败恢复逻辑；并发变更等待最多 250 毫秒。重命名只更新数据库，不访问或校验 Xray 配置 |
| 概览 | 使用独立的实时数据锁，不等待 Xray 变更锁；日用量复用小时聚合结果，减少一次统计表扫描 |
| 实时状态 `/api/rates` | 新增轻量接口；除会话验证外只读内存，不执行统计聚合 |
| 访问记录 | 保留筛选、稳定的 ID 上界和分页总数；先分页再关联用户，避免为跳过的记录执行关联查询 |
| 订阅与两种旧链接 | token 唯一索引查询，保留节点协议、域名、格式及禁用检查；未修改代理配置 |
| 首页、管理入口、静态资源 | HTML 和接口不缓存；版本化 JS/CSS 允许缓存一天，减少重复下载 ECharts |

只读 SQL 每次请求有 1 秒执行期限，统计查询最多并发 8 个；超时或数据库忙返回 503 和 `Retry-After: 1`，释放查询名额。实时状态、会话与订阅不占统计查询名额。Xray 外部命令原有 10/12 秒超时保留。

前端每 5 秒请求实时状态，完整数据按当前菜单每 15 秒更新，管理设置不查询完整统计。两个搜索表单在提交时执行搜索，替换中的访问查询会取消旧请求，隐藏页面停止轮询。GET 请求 10 秒超时，写请求 60 秒超时。

## 采集和数据兼容

日志先读取、解析，再批量写入；每轮最多处理 2000 行，事件和游标在同一事务内提交。域名增量先按用户与域名合并，缩短写锁持有时间。轮转旧日志未读完时继续保存旧文件游标，读完后才切换新文件，避免批次上限造成遗漏。

没有新增或修改表、索引、用户身份、订阅凭据、密码及代理协议。生产已确认 WAL 模式、现有索引和服务资源用量；日备份仍使用 SQLite 在线备份接口。

## 验证范围

本地使用与生产相同版本的 FastAPI、Pydantic、Starlette 和 uvicorn 验证。测试客户端需要额外的开发依赖 `httpx2==2.16.0`，不加入生产依赖、不上传生产服务器。

模拟数据为 100 位用户、100 万条访问记录、10 万条域名汇总、14.4 万条分钟流量；8 并发、220 次混合 HTTP 请求全部返回 200，P50 26.93 ms、P95 177.48 ms、最慢 223.25 ms。深页请求顺序测试中位数由 107.82 ms 降到 50.49 ms。这是本机测试结果，不代表其他硬件或无限数据规模的性能承诺。

回归验证包括：采集锁持有期间概览/实时接口仍响应；数据库写锁冲突有界返回；慢 SQL 中断后可继续查询；密码计算/统计并发上限；用户增改、启禁用、重置、失败恢复；日志分批、轮转、不重复；筛选、末页和订阅格式；改密会话、CSRF 与资源缓存。浏览器检查涵盖 5 种尺寸的 4 个页面，确认固定分页、表单提交和设置页只轮询实时状态。
